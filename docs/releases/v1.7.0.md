# SL4A_TouchScreen v1.7.0

> [!IMPORTANT]
> **Post-release Secure Boot recovery-path issue:** `v1.7.0` can check the
> upstream `/var/lib/dkms/mok.pub` path during `activate` even when Ubuntu
> DKMS actually signs with `/var/lib/shim-signed/mok/MOK.der`. The qualified
> installed/reboot path succeeded on the tested SL4 because both local
> identities happened to be usable, but the fallback/recovery check is
> distro-wrong. This is fixed on `main` by resolving the active DKMS signing
> identity in `activate` as well as `install`. A patch release will supersede
> v1.7.0 after that exact activation path is rechecked on hardware.

Surface Laptop 4 AMD / MSHW0231 production Gate5 activation release.

## What is qualified

On the tested Microsoft Surface Laptop 4 AMD unit (MSHW0231 / AMDI0060, kernel 7.0.0-31-generic):

- normal HID-over-SPI discovery and 936-byte report descriptor acquisition;
- Gate5 activation: write-only GET_FEATURE report 6 → about 5 ms → SET_FEATURE report 5;
- transition to standard-transport CapImg traffic;
- in-kernel CapImg multitouch tracker (input-quality beta);
- HID-registration DATA-drain race fix;
- cold boot;
- repeated warm reload;
- suspend/resume;
- DKMS installation;
- Secure Boot with reuse of the already-enrolled Ubuntu DKMS MOK;
- signed `sl4a-spi-amd` and `sl4a-spi-hid` modules;
- reboot with Secure Boot still enabled and automatic Gate5 activation;
- zero dropped transport frames in the qualification runs.

## Production path

```text
ACPI _PS0 -> _RST
        |
RESET_RSP -> DEVICE_DESC -> 936-byte RDESC
        |
write GET_FEATURE report 6
        |
(no synchronous GET6 body read)
        |
wait about 5 ms
        |
SET_FEATURE report 5 = 1
        |
CapImg 0x0c stream
        |
in-kernel CapImg multitouch tracker
        |
MSHW0231 Touchscreen input device
```

The default installer profile on MSHW0231 uses this standard-transport Gate5 path. The `--raw` installer option is a legacy diagnostic/research alternate transport and is not required for production multitouch.

## Still in qualification

The activation/transport path is frozen. Input-quality work continues:

- close-contact continuity;
- crossing/identity retention;
- rapid lift/re-contact;
- transient accidental third-contact handling;
- 3/4/5-finger behavior;
- edge/corner behavior;
- palm behavior;
- stylus event validation and stylus+finger coexistence;
- broader hardware, firmware, and kernel coverage.

The separate **fresh MOK enrollment** path (generate/import a new certificate → firmware MOK Manager enrollment → reboot) is implemented but has not yet been independently hardware-qualified.

## Scope

This release is qualified on one physical Surface Laptop 4 AMD / MSHW0231 unit. It is not a broad compatibility guarantee for other Surface models, firmware revisions, kernels, or MSHW device IDs.
